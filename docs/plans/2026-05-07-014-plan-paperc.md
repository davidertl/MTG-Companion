# plan: MancuTG-PaperC

## Product objective

Build PaperC as a tournament capture/review product line that shares the same backend event protocol as ArenaC.

## Priority policy (aligned with latest roadmap)

- Before ArenaC MVP completion: keep PaperC at contract/skeleton level.
- After ArenaC MVP: expand into media ingest, review queues, projector-driven tournament state, and worker runtime.

## Current in-scope baseline

- Shared schema compatibility (sessions/events/media/tournament context types).
- Skeleton emitters/builders validating shared contracts.
- No production detection pipeline, review operations, or final tournament UX.

## Post-ArenaC expansion tracks

- Capture/media ingest workflow.
- Detection normalization and confidence handling.
- Human review + correction event loop.
- Concurrent stream handling by tournament/round/table partition key.
- Tournament read models and replay/query APIs.

## Domain rules

- PaperC does not fork the base `/events` contract.
- Media artifacts stay on media path; normalized observations/corrections on events path.
- Low-confidence detection must enter review flow instead of silently finalizing.
